Troubleshooting

Find the message you're seeing below.

"command not found" or "is not recognized"​

zsh: command not found: npx
'uv' is not recognized as an internal or external command

The tool isn't installed, or your terminal hasn't noticed it yet.

  1. Close the terminal and open a new one. This fixes it most of the time.
  2. Still failing? Reinstall the tool: Node.js (for npx), uv, or Claude Code (for claude).

The dashboard-only installer stopped​

It says what went wrong and what to do. The usual ones:

  • "couldn't reach the download page" / "the download didn't finish": check your internet connection and paste the install line again. Some work or school networks block downloads.
  • "uv didn't install": open a new terminal and paste the install line again.
  • "doesn't match its published checksum": the download was damaged or changed on the way, so nothing was installed. Try again; if it keeps happening, report it.

Claude doesn't know about the skill​

  1. Make sure you started Claude Code after installing the skill. Type /exit and run claude again.

  2. Check it's installed:

    npx skills list -g

    You should see stock-analyst. If not, repeat Install the skill.

  3. You can also ask for it by name: "Use the stock-analyst skill to score AAPL."

"No price history for …"​

✗ RELIANCE: No price history for 'RELIANCE'. Check the symbol …

The ticker is wrong. Indian stocks need .NS or .BO (RELIANCE.NS), and crypto needs -USD (BTC-USD). See Tickers and markets.

The first run is slow or seems stuck​

The first time, uv downloads the data tools, which can take up to a minute. Later runs are fast. If it takes more than 3 minutes, check your internet connection and try again.

Lots of "n/a" or "Data thin"​

Yahoo Finance doesn't have full data for every stock, especially smaller companies and non-US markets. The score still works with what's available. A full report fills the gaps with web research.

"Too Many Requests" or "rate limited"​

Yahoo Finance limits how often you can fetch data. Wait a few minutes and try again, and avoid scoring dozens of stocks at once.

Claude keeps asking for permission​

When it asks, choose "Yes, and don't ask again" for the stock-analyst commands. To learn more about permissions, type /permissions inside Claude Code.

The dashboard says "The dashboard has stopped"​

The page can't reach the Chatoor server on your computer: the terminal running it was closed, or the computer went to sleep. Your data is safe. Start it again:

uv run ~/.claude/skills/stock-analyst/scripts/dashboard.py --open

or ask Claude to open the stock dashboard. The page keeps trying and reconnects by itself once the server is back.

A part of the page says "Couldn't load..." or "Something went wrong on our side"​

Something went wrong on the server or in the page. Press Try again: it reloads just that part. If it keeps happening, press Report a problem (see below).

The technical details aren't shown on screen. They're written to a log file on your computer, which Claude can read if you ask it to look into a problem:

~/.stock-analyst/logs/dashboard.log

"This page doesn't exist"​

The address is old or mistyped. Press Go to Start (or Go to the dashboard); your data is all still there.

"Couldn't load report formatting and icons"​

Some parts of the dashboard (report formatting, icons) come from the internet. Without a connection, reports show as plain text and some icons are missing; everything else works. Check your connection and refresh the page.

A red banner says files "don't match the published version"​

Some of the skill's files were changed, removed or added since you installed it. If you didn't do that yourself, reinstall with npx skills update stock-analyst -g -y. See Checking your copy.

Report a problem​

Press Report a problem: at the bottom of any dashboard page, in any error message, or on the "stopped" page. One click opens a new GitHub issue with a title and the technical details already filled in (app version, browser, recent errors on the page and the server), folded away under Technical details. Add one line about what you were doing, check it, and press Submit on GitHub. Nothing is sent until you do.

Your holdings, journal, limits, keys and file paths are never included. The issue is visible to anyone who can see the project on GitHub.

Still stuck?​

Open an issue on GitHub. Include what you typed, what you expected, and the full message you saw.
